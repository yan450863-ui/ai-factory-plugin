# AI工厂插件

[English](README.en.md) | 简体中文

AI工厂插件是一个面向 Codex 的本地插件，在同一入口提供“软件工厂”和“团队”两种协作模式，并统一管理模型名单、项目、任务、消息、决策和证据。实际创建对话、执行任务、运行命令和验收仍由 Codex 宿主完成；插件本身不启动独立模型 CLI、后台调度器或常驻守护进程。

公开版本为 **0.4.2**。显示名为“AI工厂插件”，内部插件 ID 仍为 `codex-factory`，本地市场名为 `ai-factory-plugin`。保留内部 ID 是为了兼容现有任务、技能引用和数据格式。

## 主要用途

- 在一个面板中查看项目概况和四列工作对话：名称、负责什么、当前任务、状态。
- 按模型优先级和能力等级匹配任务，并在失败时区分渠道问题与能力不足。
- 在软件工厂模式中，让总指挥只负责沟通、分派、协调和验收，具体实现由一层工作对话完成；团队模式由主对话直接制作。
- 保存任务、规则、消息、决策和证据，并按需读取，避免每轮重复注入完整历史。
- 在真实宿主会话内按需启用长任务协调，不另建后台服务。

## 两种模式

### 软件工厂

总指挥负责拆分、分派、跟进和验收，具体调查、实现、测试和返修由独立工作对话执行。默认不创建子代理，可并行使用多个一层工作对话。首页保持简洁，任务详情、内部消息、事件和证据按需展开。

### 团队

主对话直接完成核心工作，仅在搜索、资料整理、重复处理和独立核查等场景按需使用一层辅助子代理。团队模式不读取工厂项目、任务、规则或历史。

两个模式共享 Codex 当前可见的模型目录，但启用状态、并行上限、是否保留在当前对话、是否允许子代理等设置分别保存。两个开关同时开启时，插件不会额外创建执行对话。

### 长任务协调

协调助手默认关闭。项目需要时，可选择要监控的一个或多个工作对话和一般处理范围，并由真实宿主线程绑定后启动；每个项目最多一个协调者。它处理一般进展、依赖、必要信息和限额内返修；需求、验收、架构变化和范围扩大等关键事项仍升级给总指挥。协调依赖宿主会话存活，不是可无人值守运行的后台任务。

## 安装要求

- 支持本地执行器和 Agent Plugins 的 Codex 版本。
- Node.js 22 或更高版本，且 `node`、`npm` 在 `PATH` 中。
- 能运行 `codex` CLI，并允许安装本地插件市场。

Windows 推荐使用 PowerShell 7（`pwsh`）。仓库中的安装脚本会先检测构建依赖，缺失时执行 `npm ci`，然后构建插件、注册本地市场并安装 `codex-factory@ai-factory-plugin`：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\工具\install.ps1
```

安装后可在 Codex 的插件管理中启用或打开“AI工厂插件”。若当前窗口仍显示旧面板，关闭后重新打开；必要时在插件管理中禁用再启用。

### 手动构建与安装

```powershell
cd .\工具
npm ci
npm run build
cd ..
codex plugin marketplace add .\插件市场
codex plugin add codex-factory@ai-factory-plugin
```

Linux/macOS 可使用相同的 `npm ci`、`npm run build` 和 `codex plugin` 命令；Windows 专用安装脚本不适用于这些平台。

### 发布包区别

- **完整源码包**：包含 `插件市场/`、`工具/`、源码、构建产物、许可证和 CI，适合自行构建、审查和安装。
- **单插件包**：根目录直接包含 `plugin.json`、`mcp.json`、`dist/`、`assets/`、`skills/`、`references/` 和许可证，便于检查或将插件目录接入本地插件市场。

## 数据位置

插件不包含遥测或外部数据服务。项目和任务数据保存在本机：

- Windows 默认：`%LOCALAPPDATA%\CodexFactory`
- Linux/macOS 默认：`$XDG_DATA_HOME/codex-factory`；未设置时为 `~/.codex-factory`
- 可用 `CODEX_FACTORY_DATA_DIR` 覆盖数据目录。
- 项目根目录另有一份 `.codex-factory/project.json` 主副本。
- 模型设置位于数据目录下的 `models/settings.json`。

公开版本不会自动读取作者机器上的旧模型团队目录。仅当显式设置 `CODEX_FACTORY_LEGACY_DATA_DIR` 时，才会尝试导入该目录中的旧设置；未设置时不执行机器路径迁移。

项目路径、任务、消息和证据属于本地工作数据，是否纳入版本控制由使用者自行决定。

本地保存不等于完全离线运行。执行任务时，相关提示、上下文和工具结果会发送给使用者选择的模型服务，并遵循该服务提供方的隐私政策和服务条款。

## 用户实测与费用边界

用户反馈：在其实际工作流中，主对话消耗降至原来约 **1/10**，但消耗主要分摊到执行对话或辅助对话。可以接入更适合任务且价格更低的模型，以降低主对话负载和上下文压力。

这是用户自述的工作流观察，不是本项目提供的公开复现实验、样本统计或账单审计。**总 token、总调用量和总费用不保证下降 10 倍**；实际费用取决于各模型定价、调用量、重试和返工。主对话负载下降也不等于整体费用同比下降。

## 已知限制

- 插件依靠 Codex 宿主创建和继续原生对话，不能脱离宿主独立执行。
- 保存任务、发送消息或点击按钮只表示请求已登记，不代表原生任务已经启动或仍在运行。
- 长任务协调依赖宿主对话和原生有界等待；宿主退出后不能保证继续监控。
- 协调权限和角色边界主要依靠技能与持久任务约束，不是宿主的强制权限系统。
- 真实跨聊天协调的长期、无人值守运行尚未作为独立场景验证。
- 旧版本缓存可能被运行中的宿主占用；升级时应使用新版本号并重新安装，不要手工修改缓存。

## 开发与验证

```powershell
cd .\工具
npm ci
npm run build
npm run verify
```

`npm run verify` 在临时目录中运行 MCP 协议、核心存储、模型设置和隔离 UI 检查，不读取真实用户数据。安装后可额外运行：

```powershell
node .\工具\verify-host.mjs
```

该命令启动独立的 Codex app-server，检查已安装插件是否暴露 13 个 MCP 工具以及团队/协调技能；它需要本机 Codex 宿主，因此不在 CI 中运行。

构建输出写入 `插件市场/plugins/codex-factory/dist/`，不生成 source map。CI 使用 `npm ci`、构建和不需要宿主的检查。
