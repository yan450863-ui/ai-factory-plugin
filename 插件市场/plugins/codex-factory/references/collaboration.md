# 工厂与团队共用协作规则

本文件是通用协作规则的唯一原件。角色技能只保留入口、角色边界和必要约束，需要通用细节时读取本文件。

## 角色与层级

- 软件工厂总指挥只做需求判断、分派、协调和验收；具体调查、实现、测试、排错和返修由同一层工作对话完成。
- 团队主对话是核心制作主体，直接完成实现、测试和返修；辅助子代理只处理明确、可独立交付的搜索、整理、重复处理或核查。
- 两种模式都只允许一层执行或辅助，不得继续创建下属、递归分派或通过换名绕过限制。

## 原生工具与状态

- 使用宿主原生代理、等待、读取和中断工具；不启动模型 CLI、外部调度器、常驻服务或前端定时器冒充后台运行。
- 原生创建或继续前先准备完整参数包：prompt、具体 model、宿主支持的 thinking/effort 和 target。缺字段拒绝，不靠宿主默认模型补齐；schema 错误重试保持同一参数包，只修具体字段。
- 权限拒绝、用户取消和任务错误不自动换模重发；响应不明确先核对真实线程。插件不能拦截绕过它的原生调用，流程门禁不是宿主权限系统。
- 保存 thread/session 引用只表示记录，不表示在线或正在执行。旧心跳只能提示待核实，不能据此宣称已停止。
- 设置开关只影响后续派发，不终止已经运行的执行者。用户取消、权限拒绝和任务错误不换模。
- 任务指定、启动请求和宿主报告分开；`assignedModel` 只保留历史且未核实，换 thread/session 后旧归因失效。

## 上下文与通信

- 首次领取任务读取完整任务、需求、规则、验收和授权边界；后续先读状态与版本，只有任务或需求版本变化时才重取完整版本。
- 默认项目上下文只取项目/工作状态和版本；需求、规则、决定、事件按需展开。不得用摘要冒充完整任务。
- 通信只传变化、结论、检查、引用、阻塞或决定。不发送完整日志、隐藏推理或整段任务；引用要能定位原件和版本。
- 消息正文只在 store 持久化一处。宿主通知只带项目、任务、消息 ID 或游标；通知失败要明确未送达，并可按引用恢复。
- 读取优先使用增量游标和有界等待；无变化不重复汇报，不固定短周期轮询全文。

## 等待与无变化

- 有实质变化就处理；没有变化时保留当前会话，使用宿主原生 `wait_threads` 加 `afterCursor` 做有界等待，不持续激活空转。
- 等待超时本身不算失败，也不催问。只有达到约定无进展阈值时，才检查一次状态、依赖或阻塞；没有新证据就继续等待或按授权结束。
- 阶段完成、用户暂停、异常恢复或换模时停止当前等待，需要时再重新开始，不把旧等待当成在线证明。
- 不新建常驻服务、调度器或前端定时器；等待仍消耗宿主资源，不得宣称等待免费。

## 写回执与验收

- 写操作只返回回执：对象 ID、revision、任务版本、状态和必要冲突信息；完整对象只供面板或明确的全量读取使用。
- 任务范围、验收、授权对象和不可逆操作边界不能为了节省字符而省略。
- 完成前运行与改动对应的真实检查，记录命令、退出码、日志路径和摘要。没有 usage 证据时不得宣称节省 token 或费用。
