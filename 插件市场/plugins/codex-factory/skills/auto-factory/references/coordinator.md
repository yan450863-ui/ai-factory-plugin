# 长任务协调

协调助手默认关闭，一个工厂项目最多一个，优先复用已有协调工作对话。只有用户明确需要持续跟进时才开启；普通项目不自动创建。

主对话先调用 `factory_coordinator op=get` 查看状态，再用 `op=enable` 保存明确的目标工作对话、授权消息对象、一般处理范围、等待预算和项目版本。配置成功只表示待启动，不代表线程在线。宿主创建或复用一层协调工作对话后，通过 `factory_task save roleKind=coordinator` 绑定真实 thread；协调者用完整任务读取确认目标、授权对象、一般范围、版本和真实线程引用，再调用 `op=start`。

协调者只处理已授权范围：进展汇总、依赖提醒、必要信息补充、原执行者有限返修和自验。需求/验收/架构变化、范围扩大、不可逆操作、安全阻塞、超限重试、更换未授权模型、创建新线程或额外代理，必须立即请示总指挥。

监控使用宿主原生 `read_thread`、`wait_threads`（`afterCursor` 和有界等待）或工厂增量消息，不为固定短周期反复读取全文。没有实质变化时保留会话等待，超时不失败、不催问；达到约定无进展阈值才检查一次。阶段完成、用户暂停或异常恢复/换模时停止等待再按需重开。每轮检查写 `heartbeat` 和游标。停止按钮只写停止请求并通知宿主；宿主确认中断后写 `stop`。宿主退出或心跳过期只能显示“待核实/可能失联”，不能据此宣称任务停止，也不能用前端定时器或后台服务冒充常驻运行。
